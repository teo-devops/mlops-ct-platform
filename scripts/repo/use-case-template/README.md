# Use case: __UC_TITLE__

<!-- What it predicts, for whom, from which data. Two or three lines. -->
Given a request with `x1, x2, x3, zone`, predict __MODELS_PROSE__. Generated by
`make new-use-case`; the data is synthetic until `plugin/src/__UC_PKG__/data.py` reads the real source.

## Quick start

```bash
make use-case ENABLE=__UC__ COMMIT=1      # deploy it (a commit; Argo CD creates its workloads)
make demo USE_CASE=__UC__                 # cluster → platform → this use case → smoke   (≈15 min)
```

On a cluster that already runs the platform, `USE_CASE=__UC__ make build pipeline smoke` is enough.
When it ends, `make status` prints the UIs; the API is at http://__UC__.localhost:8088/docs.

## Play

**1. Ask it something**

```bash
curl -s -X POST http://__UC__.localhost:8088/v1/__UC__/predict \
  -H 'content-type: application/json' -d '{"x1": 1.0, "x2": 2.0, "x3": 0.3, "zone": "north"}' | jq
```

**2. See where that answer came from**

| | |
|---|---|
| the pipelines that trained v1 | http://argo.localhost:8088 → namespace `__UC__-pipelines` |
| the gate decision, the registry | http://mlflow.localhost:8088 → experiments `__UC__/<model>`, models `__UC__-<model>` (aliases `champion` / `previous`) |
| the deployment | http://argocd.localhost:8088 → `__UC__-serving` and `__UC__-api` |
| the dashboard | http://grafana.localhost:8088 → *CT Loop*, variable `use_case = __UC__` |

**3. Break a model**: `kubectl -n __UC__-serving scale deploy/<model>-predictor --replicas=0` → the API answers
503 (add a fallback in `api/app/main.py` and declare it in `usecase.yaml` `degradable_model` if the
business allows one).

**4. Close the loop**: `make drift USE_CASE=__UC__` — the data source switches to the `drift` profile,
traffic from that world hits the API, the monitor retrains, promote commits, the new version is served.

**5. Roll back**: `make rollback MODEL=<model> USE_CASE=__UC__`.

More in [docs/runbook.md](docs/runbook.md); the instance architecture in [docs/architecture.md](docs/architecture.md).

## Layout

```
usecase.yaml   what the platform's flow scripts need (models, API host/path/sample, drift profile)
docs/          architecture of the instance, runbook
plugin/        the `UseCase` implementation (ingest, schema, build_model, evaluate) + the steps image
api/           FastAPI: one request in, every model out, lineage; telemetry and KServe client from libs/ctserve
workloads/     api/ · serving/ · pipelines/ — one Helm chart per workload (templates are the platform's)
```

Isolated like every use case: namespaces `__UC__-{api,serving,pipelines}`, buckets
`__UC__-{models,datasets,predictions}`, users `__UC__-{reader,pipeline,api}`, NetworkPolicies that admit
only its own namespaces. Nothing here names another use case (the validator checks).
